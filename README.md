# Content OS

레퍼런스 하나를 **증거가 붙은 발행 후보**로 바꾸는 콘텐츠 운영 시스템.
내 컴퓨터에 설치해서 쓰는 오픈소스 앱입니다.

근거를 연결하고 직접 확인한 초안만 최종 검토와 발행 기록 단계로 진행합니다.
실제 SNS 게시는 각 플랫폼에서 직접 합니다. AI는 초안·채점·평가를 추천하고, 확정은 사람이 합니다.

```text
수집·소스 정리 → 직접 작성 / 선택적 AI → 근거 확인·최종 검토 → 직접 게시·발행 기록 → 교훈
```

## 현재 상태 — 2026-09-06

- 회원이 각자 설치하는 1인용 앱입니다. 사용자 계정·팀·멀티테넌시는 범위 밖입니다.
- 로컬 기본 사용, 선택적 Gemini·Supabase 연결을 유지합니다.
- 필수 검토 규칙 통합, 버전별 검토, 발행 원본 보존, 작성자 설정, 소스의 주장·근거 정리, 백업·복원을 구현했습니다.
- 검토의 필수 조건은 도입부·본문·핵심 주장, 작성자 경험·구체성·상투성 점검, 연결된 자료에 대한 사람의 확인입니다. 문제·해결 구조, 고유 관점, 다음 행동 점검은 개선 권고입니다.
- 본문·주장·자료 변경은 근거 확인과 최종 검토를 무효화합니다. 발행 원본은 수정하지 않고 새 수정본을 만듭니다.
- 발행 기록은 실제 게시 확인, 게시물 링크, 기록 시각을 보관합니다. 과거 발행 상태에 링크나 검토 이력이 없으면 미확인 기록으로 표시합니다.
- 전체 깊은 저작 모드와 캘린더는 아직 구현하지 않았습니다. 발행 후 교훈 한 줄을 기록하는 작은 학습 기능만 제공합니다.
- 검증: 회귀 테스트 28개, 정적 검사, 프로덕션 빌드 통과. 브라우저에서 직접 작성·검토·발행 기록·수정본·백업 복원을 확인했습니다.
- 실제 Supabase에는 아래 안내에 따라 별도로 마이그레이션을 적용해야 합니다.

## 설치하고 첫 콘텐츠 만들기

Node.js와 npm을 준비하세요. 아래 명령은 Git이 설치된 경우입니다.

```bash
git clone https://github.com/bk20260126-code/content-os.git
cd content-os
npm ci
npm run dev
```

ZIP으로 받았다면 압축을 풀고 **package.json이 있는 폴더**를 터미널에서 연 뒤 `npm ci`, `npm run dev`를 실행하세요.
`http://localhost:3000`을 열고 터미널을 켜 둡니다. 계정·DB·API 키 없이 직접 작성할 수 있습니다.
개발 모드의 첫 실행에는 연습용 소스가 보입니다. 클라우드 또는 프로덕션 모드에는 데모를 자동으로 넣지 않습니다.

1. **설정 · 백업**에서 독자·목적·말투를 적습니다. 생략해도 직접 작성할 수 있습니다.
2. **수집 → 소스 추가**에서 제목과 메모를 적고 핵심 주장·출처·날짜·인용 또는 관찰·미확인 사항을 정리합니다.
3. **이 소재로 직접 작성 → 직접 작성**을 누르고 도입부·본문·핵심 주장을 적습니다. 채점·승급은 소재를 비교할 때 선택해서 사용합니다.
4. 자료를 등록·연결하고 원문이 핵심 주장을 뒷받침하는지 직접 확인합니다. 필수 조건을 확인한 뒤 **내용·근거 최종 확인하고 리뷰로 이동**을 누릅니다.
5. 실제 게시 후 **발행 관리 → 실제 발행 기록하기**에서 게시물 링크와 게시 확인을 남깁니다.

자세한 안내는 **[사용 가이드](docs/GUIDE.html)** 를 브라우저로 여세요.

## 저장 · 백업 · 복원

상단에서 이 기기 저장·클라우드 저장·대기·실패 상태를 확인합니다.
기본 저장은 해당 브라우저에만 남습니다. 브라우저 데이터 삭제 전에 **설정 · 백업 → 전체 백업 내려받기**를 사용하세요.
백업에는 근거 설명과 링크가 들어가며 외부 파일 자체는 들어가지 않습니다.

복원은 파일 검증 → 개수 미리보기 → 기존 사본 백업 → 교체 순서입니다. 기존의 schemaVersion 1 JSON도 가져올 수 있습니다.
손상·미지원 버전은 자동 저장을 중단하고 원본 내려받기와 복원을 안내합니다.
다른 탭에서 수정했다면 오래된 탭의 덮어쓰기를 막습니다. 현재 작업을 백업한 뒤 새로고침하세요.

클라우드 저장은 서버 버전을 비교해 충돌을 감지합니다. 오프라인의 미저장 변경을 서버 사본으로 자동 덮어쓰지 않습니다.
**클라우드 사본 비교**에서 양쪽 백업을 확인하고 유지할 사본을 선택합니다. 자동 병합은 하지 않습니다.

## AI 기능 켜기 (선택)

AI 채점·초안 생성·게이트 평가를 쓰려면 Gemini API 키가 필요합니다.
[Google AI Studio](https://aistudio.google.com/apikey)에서 키를 발급받고 본인 계정의 이용 조건을 확인하세요.

```bash
cp .env.example .env.local
```

`.env.local`에 키를 넣으세요.

```bash
GEMINI_API_KEY="발급받은_키"
```

**키 없이도 직접 작성·직접 채점·검토를 사용할 수 있습니다.** AI가 실패하면 오류를 안내하고 직접 작성을 선택할 수 있습니다. AI 평가에는 작성자 설정, 소스 브리프와 연결한 근거 설명을 전달하지만, 링크나 파일을 자동으로 열어 검증하지는 않습니다.

## 여러 기기에서 쓰기 (선택)

기본값은 localStorage라 브라우저를 지우면 데이터도 사라지고, 다른 기기와 공유되지 않습니다.
클라우드에 저장하려면 본인 [Supabase](https://supabase.com) 프로젝트를 연결하세요. 사용할 플랜과 저장 용량은 본인 환경에 맞게 선택하세요.

1. Supabase에서 새 프로젝트를 만듭니다
2. SQL Editor에서 `supabase/migrations/` 안의 파일을 **번호 순서대로** 실행합니다. 기존 사용자는 먼저 전체 백업을 내려받고 새 `20260906000000_versioned_snapshots.sql`을 적용합니다.
3. `.env.local`에 추가합니다

```bash
SUPABASE_URL="https://<프로젝트-ref>.supabase.co"
SUPABASE_SERVICE_ROLE_KEY="본인_service_role_키"
NEXT_PUBLIC_STORE_BACKEND="supabase"
```

새 마이그레이션은 기존 테이블을 삭제하지 않고 버전이 있는 상태 사본 테이블과 원자적 저장 함수를 추가합니다.
처음 명시적으로 수정·저장할 때 기존 데이터를 새 사본에 보관합니다. 구버전 앱의 버전 없는 저장 요청은 거부합니다.
마이그레이션이 없으면 기존 클라우드 데이터를 읽되 새 변경은 기기에만 보관합니다. 상단에 업데이트 필요를 안내하며, 마이그레이션 후 사본 비교를 통해 클라우드 저장을 활성화합니다.
코드를 이전 버전으로 되돌리는 것만으로 새 데이터를 되돌릴 수는 없습니다. 되돌리기 전 최신 전체 백업을 확보하세요.

`service_role` 키는 서버에서만 쓰이고 브라우저로 절대 나가지 않습니다.
`NEXT_PUBLIC_` 접두사를 붙이지 마세요.

## 인터넷에 올릴 때

로컬에서만 쓴다면 이 단락은 건너뛰세요.

배포하면 앱 전체가 HTTP Basic 인증으로 잠깁니다. 아이디와 비밀번호를 설정하지 않으면
**서버가 503으로 닫힙니다** — 설정을 깜빡해서 service_role API가 열리는 일이 없도록
일부러 그렇게 만들었습니다.

```bash
APP_ACCESS_USERNAME="아이디"
APP_ACCESS_PASSWORD="길고_무작위인_비밀번호"
```

반드시 HTTPS로만 배포하세요.

## 이 앱은 1인용입니다

사용자 계정이나 팀 기능이 없습니다. 한 사람이 자기 기기에서 자기 데이터로 쓰는 도구이고,
그래서 설치가 간단합니다. 여러 사람이 쓰려면 각자 설치하면 됩니다.

## 서체

본문은 [Pretendard](https://github.com/orioncactus/pretendard)(SIL OFL), 제목은 Gmarket Sans입니다.

Gmarket Sans 파일은 **일부러 저장소에 포함하지 않았습니다.** 무료로 쓸 수 있는 서체지만
재배포 허용 여부가 명확하지 않아, 설치된 서체만 참조합니다. 없으면 Pretendard로 표시되며
레이아웃은 그대로입니다. 원한다면 [지마켓 서체 페이지](https://corp.gmarket.com/fonts)에서
무료로 받아 설치하세요.
